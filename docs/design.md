# goasm design

## Why

A template JIT usually has one hand-written function per bytecode
instruction, each a run of emitter calls:

```go
c.e.Movz(X24, uint16(src1), 0)
c.e.LdrReg(X24, RegBP, X24)
c.e.Movz(X25, uint16(src2), 0)
c.e.LdrReg(X25, RegBP, X25)
c.e.AddReg(X24, X24, X25)
```

That is hard to read as assembly, easy to get subtly wrong, and has to be
written again for every architecture. goasm lets you write the sequence as
assembly in a template file and generates the Go method from it. The JIT
compiler calls the generated `EmitXxx` methods and stays the same on every
architecture.

## Pipeline

```
templates/<arch>.goasm --template.Parse--> []Template + aliases
                       --gen.Encoder----> one Go statement per instruction
                       --gen.Generator--> emit_<arch>.go (gofmt'd)
```

- `template` parses the file. It knows nothing about architectures.
- `gen.Encoder` (one per architecture) turns one instruction into a Go
  statement, usually one method call on the `Emitter`.
- `gen.Generator` wraps the statements in a method per template, adds the
  header (`// Code generated by goasm. DO NOT EDIT.`, `//go:build <arch>`,
  `package jit`) and formats the result.

## Template format

```asm
# A comment: any line starting with # that is not a directive.

# ALIAS BP = X22                  register alias, file-wide

# TEMPLATE Name(p1 uint8, p2 int) (ret1 int, ret2 int)
    MNEMONIC op1, op2, op3        # trailing comment
```

- **`# ALIAS name = register`** gives a register a role name. Aliases apply
  to the whole file, so a template can say `BP` instead of `X22`.
- **`# TEMPLATE Name(params) (results)`** starts a template. Parameters are
  `name type` pairs and become the Go method's parameters. Results are
  optional: `(a int, b int)`, `(int)` or a bare `int`.
- **Instructions** are the lines after a `# TEMPLATE`, up to the next one. A `#`
  followed by a digit or `-` is an immediate (`#8`, `LSL #3`), not a
  comment.
- **Parameters** can appear wherever a register or an immediate can. A
  parameter in a register position is passed as the register number, so
  `STR reg, [SP, #0]` with `reg int` stores whatever register the caller
  names.
- **Branch placeholders.** `B.EQ 0 -> name` emits a conditional branch with
  no target yet and assigns its code offset to the result `name`. The method
  returns the offsets, and the JIT patches them once the targets are known.
  This is the only branch form that works on both architectures (see
  Limitations).

## The Emitter contract

Generated code calls methods on `*Emitter` with register numbers and
immediates, for example:

| template line (arm64)          | generated call            |
|--------------------------------|---------------------------|
| `ADD X24, X24, X25`            | `e.AddReg(24, 24, 25)`    |
| `ADD SP, SP, #8` (SP = X21)    | `e.AddImm(21, 21, uint64(8))` |
| `LDR X24, [BP, X24, LSL #3]`   | `e.LdrReg(24, 22, 24)`    |
| `MOVZ X24, slot`               | `e.Movz(24, uint16(slot), 0)` |
| `B.EQ 0 -> j`                  | `j = e.BcondPlaceholder(int(CondEQ))` |

The consumer's `jit` package supplies the `Emitter` type, the methods the
generated code calls, and constants such as `CondEQ`. The set of methods
needed is whatever the generated file calls, and the Go compiler lists any
that are missing. `gen/testdata/jit/emitter.go` is a complete arm64
`Emitter` for the test templates, and a test type-checks the generated arm64
fixture against it.

For amd64, the encoder maps Intel-style operands onto the same method names:
`MOV RAX, [BP + RCX*8]` becomes `e.LdrReg(0, 3, 1)` with `BP = RBX`. Register
numbers follow the x86 encoding (RAX=0 ... R15=15; XMM0-7 = 0-7). The
`Emitter` decides what bytes each method writes.

## Testing

- `gen/testdata/templates/*.goasm` are fixture templates that exercise
  most of what each encoder supports.
- `TestGoldenEmitters` regenerates `gen/testdata/jit/emit_*.go` from them and
  requires byte-identical output. A change to the generator therefore shows
  up as a fixture diff.
- `TestARM64EmitterTypeChecks` type-checks the arm64 output against the
  reference `Emitter`, on any host.
- The encoder tests in `gen/enc_test.go` check single instructions.

## Limitations

- **The package name is fixed.** Output always declares `package jit`.
- **Branches to labels are not implemented.** Labels (`.loop:`) parse, but
  an unconditional branch to one (`B .loop`) generates a `// TODO` comment
  instead of a branch, on both architectures. A conditional branch to a
  label is an error on arm64 and another `// TODO` comment on amd64. Use the
  placeholder form and patch the offsets in Go.
- **Some operands are miscompiled instead of rejected.** The amd64 encoder
  passes an operand it does not recognise through unchanged, so `ADD SP, 8`
  (no `#`) becomes `AddReg(SP, SP, 8)`, which adds register R8. Write
  immediates with `#`.
- **`MOVK` with a wide parameter keeps only the low 16 bits.** On arm64,
  `MOVK X25, p, LSL #16` with `p uint64` passes `uint16(p)`, not
  `uint16(p >> 16)`, so a `MOVZ`/`MOVK` sequence over one 64-bit parameter
  repeats its low half. Use `MOV X25, p`, which calls `MovImm64`.
- **amd64 has no reference Emitter** in this repository, so its fixture is
  checked as bytes only.

## Prior art

- [DynASM](https://luajit.org/dynasm.html) (LuaJIT) is a preprocessor that
  mixes assembly into C, for many architectures. goasm is the same idea in a
  much smaller form: Go code generation, no preprocessor.
- [asmjit](https://asmjit.com) is a C++ JIT assembler library with a builder
  API.
